# 语音结果界面

正常说完后，沿用既有自动输入设置。用户不需要理解 ASR、文字处理请求、输入控件核验或确认令牌。

需要人工检查时，界面只提供“输入”和“复制”。“输入”把当前显示的文字输入到录音时同一窗口内、用户当前选择的普通输入框及光标位置。位置核验由程序在一次点击中完成；跨窗口、密码框、非空选区及粘贴前再次变化仍被拒绝。没有可靠输入控件时直接提供“复制”，提示在输入框中粘贴，不显示可点击却无法完成的输入按钮。

文字被自动修改且与用户说的话不同时，提供可选“撤销修改”／“恢复修改”；这只改变待输入文字，不会插入或复制。输入与复制使用当前显示的版本。修改失败时显示“再试一次”，复用本次已有文字，不需要重说；成功结果不再持续展示重试操作。

“语音检测未确认讲话”在界面显示为“这段话可能听错了，请检查一下。”此处只改用户文案，未改人声检测算法、阈值、音源或自动输入放行条件。底层详细错误仍保留在已有 IPC 状态中供诊断，不展示为用户必须理解的步骤。

“复制”成功后保留五秒“已复制”反馈和粘贴提示；终端按配置中的终端类别显示 Ctrl+Shift+V，其他窗口显示 Ctrl+V。复制失败保留文字并明确提示重试，不显示复制成功。成功输入或复制后，本次结果仍只能消费一次。

内部 `review`／`confirm` 协议继续存在。UI 的 `insert-current` 在用户主动点击“输入”时，取得当前安全控件快照并紧接着确认；后续 `Desktop::paste` 的同窗口、控件、光标、选区、内容及剪贴板准备后的复验全部保留。自动输入和指令替换仍绑定原始目标，不使用该手动重定向路径。最终检查至快捷键发送依旧不是跨进程原子事务，没有应用接收回执，不能宣称绝对无竞争。

隔离验收复用 `tests/retry_desktop_test.py` 的私有 GTK／AT-SPI／零样本 PipeWire／loopback HTTP 夹具，附加流程见 `tests/result_actions_cases.py`。没有新增测试专用生产命令、读取真实麦克风或发送真实用户数据。后续 Chromium 网页输入兼容见 [browser-input.md](browser-input.md)。kitty 保留复制粘贴回退。
