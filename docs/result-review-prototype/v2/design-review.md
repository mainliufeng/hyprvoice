# 结果检查设计 v2 · A 已委托审查确认

推荐 A「雾白靛蓝」作为默认方向；B「暖纸松绿」用于阅读风格对照。两方案共享相同状态、动作及标注语义，只改变视觉节奏、字体与主色。此交付仍是原型，未批准生产实施。

## 对上一版的重新判断

用户明确认为 v1 粗糙、单调、细节不足，按钮也过于朴实。原先 QA 的 passed 已撤回，v1 归档为未获批准。此前测试能说明按钮能点击、草稿能恢复，不能证明设计质量合格。

旧版有五处主要问题：

- 正文350字重偏轻，来源9 px、目标10 px偏小；浅灰层级使关键内容与说明混在一起。
- 每处差异都用双层词块，抬高中文基线，破坏正常读句子的节奏。
- 编辑框像浏览器默认表单，缺少正文连续性、草稿反馈和退出路径。
- 动作多数只是同级文字，复制、编辑、F9与确认输入的用途和优先级不够清楚。
- 异常、文字版本与ASR差异缺少统一而明确的状态表达，也没有演示完整的多轮修改衔接。

## 新版设计决定

面板宽552 px。正文17 px、400字重、A行距28 px/B行距29 px；来源和状态至少12 px。A使用 Noto Sans CJK SC，B正文使用实际安装的 Noto Serif CJK SC，界面说明仍用无衬线体。A更适合高频操作和校对，因此推荐A。

默认只读一份正文，复制是熟悉的图标动作，编辑用图标加文案，语音修改保留文字与F9提示，确认输入采用深色主按钮和回车图标。关闭、复制、撤销、展开等使用官方 Lucide 的同一套24 px网格、2 px笔画资产。图标有可访问名称和悬停提示；关键动作不只靠图标猜含义。常用图标命中区至少36 px，主次按钮38 px高，主按钮最小112 px，处理期间宽度不跳动。

校对模式中，差异词用轻琥珀底与点状下划线定位。只展开一处，在同一正文下方展示该片段的当前/备选两行，来源分别标明；没有覆盖正文的浮动层，也没有每个词的双层大chip。可以点击备选，也可以确认保留当前词；两条路径都更新检查状态。切回阅读模式后标记隐藏，保留一份当前正文。

文字修改比较与音频候选分开。新增用绿轻底及下划线，删除用珊瑚轻底及删除线，替换用蓝轻底及前后对照；另有文字图例，不依赖颜色本身。仅在“查看修改”中显示，普通阅读仍干净。没有提供虚构置信度，也没有将F9改写当作另一份音频识别。

编辑态沿用正文的字体与排版，用轻边界表达输入区，独立显示草稿状态和字数。暂不应用不会改正文，刷新后可继续；有未应用草稿时不能直接用F9覆盖。手动编辑或F9生成新版后，旧ASR候选停止替换当前正文。

中断只用整体提示，说明可能不完整，不标造具体错字位置。收尾演示保留预览，处理有效音频后可增长；失败退回最后预览，无预览且失败时明确没有结果。F9修改后中断提示仍在。所有复制/输入演示只读取当前正文，不混入标记或来源。

语音修改有独立要求、原正文、处理中、失败、V2/V3和撤销路径。任意入口都展示要求，撤销恢复修改开始时的实际正文（包括手动编辑），不是退回最初固定样例。失败标题明确“这次修改未完成”，副标题说明保留上一版，版本标记为“V2 · 已保留”，不会同时宣称本次已成功。

## 验收边界

`interaction-checks.json` 是在 IAB 实际操作界面后的观察记录，不是模型/API/录音测试。`contrast.json` 是本地颜色计算。原生GTK焦点、Cornice输入目的地、真实麦克风、ASR故障恢复和系统剪贴板回读仍需用户批准后单独验收。本轮没有改生产代码、合 main、push、安装或重启服务。
