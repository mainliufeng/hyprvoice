# 忠实纠错与主动整理的策略验证

本轮将两种内置默认策略的边界写清楚，不更改自定义 `prompts`、默认后端、模型、前文开关或范围。默认场景仍为 `raw`。已在配置中明确覆盖 `correct` / `format` 的用户继续使用自己的文案，升级不会替换已有配置。

| 场景 | 允许操作 | 必须保留 |
| --- | --- | --- |
| `correct` 忠实纠错 | 有依据的识别错词、标点 | 原措辞、语序、口头重复、语气；上下文不足不猜 |
| `format` 主动整理 | 无意义重复、语序、标点、分段 | 所有事实与立场；有意义强调及引用原话不能删改 |

两种策略都保护金额、日期、小数、版本号、否定、条件、不确定性和专名的正确名称，中英混说不主动翻译。前文仅作读音与词形依据；本次新增文字不能重复或修改前文、展开代词或补写猜测事实。选区指令遵从本次明确修改要求，例如明确改金额时允许改数字，其余未要求修改的事实与否定仍须保留。自定义策略继续通过生产请求传输，不替换成内置文案。

## 合成测试数据

`tests/fidelity_cases.json` 是专门为测试编写的公开合成文字，不包含录音、转录或用户输入框内容。共 12 组，包含金额与否定、日期/小数/版本号、嵌套否定与条件、前文专名读音对应、中英混说、引语与不确定性、有意义强调、主动整理顺序、前文不重复、引用中的指令作为数据、未知名不猜、明确选区改金额。

每组提供 `correct` / `format` 的人工固定示例、需保留片段、禁止片段和刻意损坏的响应。这些响应由测试 HTTP 服务直接返回，**没有模型生成或模型评分**。片段检查只是这些固定用例的回归准则，不能检查任意自然语言的等价含义，也不是应用的语义安全过滤器。

## 自动测试

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DHYPRVOICE_WITH_FUN_ASR=OFF
cmake --build build -j2
ctest --test-dir build --output-on-failure
# 仅运行本轮接口/策略合同：
python3 tests/fidelity_http_test.py build/fidelity_probe tests/fidelity_cases.json
```

`fidelity_probe` 使用生产 `Config` / `ProcessText` / `Rewrite`；Python 服务只监听随机 `127.0.0.1` 端口，配置使用显式假模型名和测试密钥。7 个测试方法涵盖：

- 两种默认策略区别与保护要求；12 组 × 2 场景的请求和固定正例。
- 12 组 × 2 场景的刻意坏响应：合成评分发现损坏，同时确认生产目前会接受有效非空 UTF-8 响应，避免把“模型返回了文字”误报成“内容保真”。
- 自定义 prompt 原样覆盖；选区指令路由优先于普通场景。
- `transcript` / `selected_text` / `recent_input`（含换行、引号、反斜杠）原样以用户 JSON 数据传输，系统策略不混入数据。
- HTTP 失败、空结果时，普通模式保留原文；指令模式返回空文字，不能把口述指令写入选区。
- 失败后的重试复用原转录、场景、选区和前文，请求正文逐字节一致。

日志不打印请求文字、选区、前文、HTTP 正文或环境密钥。超时、取消、迟到响应、重复操作和新录音竞争继续由既有 `retry_http_contract` 及隔离桌面测试覆盖。

## 证据边界

本轮证实策略路由、数据传输、回退与重试合同；**真实模型保真提升未证实**。应用没有通用语义校验器，模型仍可能改错事实、遗漏否定、误猜专名。原文与手动确认继续提供恢复路径；人工固定正例不算真实模型正确率。

测试不需要 ASR、麦克风、桌面或外部付费模型。Fun 与 X-ASR 音频识别质量、真实 Fun-ASR/llama.cpp worker 构建、Android/终端/Chrome 的目标定位和插入支持不由这套文本测试证明；这些必须分别按音频构建及桌面目标保护报告说明，不能外推。
