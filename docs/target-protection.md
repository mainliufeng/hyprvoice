# 同窗口输入位置保护

普通听写沿用自动输入设置。Chrome、独立 Electron 窗口、Ghostty 和其他缺少完整输入框信息的应用仍可直接输入；无需用户操作内部位置确认步骤。

录音绑定原窗口地址、进程和稳定标识。窗口切换事件是不可清除的自动输入阻断条件，即使录音结束前已返回原窗口，也保留文字等待用户点击“输入”。剪贴板准备完成后再次检查原窗口，只发送一次粘贴快捷键，不发送 Enter，也不自动提交表单。主动点击“输入”只能向原窗口当前光标输入。

对于可核验 GTK／Chromium 编辑控件，控件身份、光标、选区、字符数和本地全文 SHA256 继续参与核验。文字最多 65536 个字符，不截断后假称完整核验；录音期间控件、位置或内容变化以及原先可靠的控件失去核验能力，都不能自动降为窗口检查。普通听写不覆盖已知选区，确认的密码框、只读控件和浏览器地址栏仍被拦截。

缺少输入框信息的普通听写只依赖原窗口检查；无法保证同一窗口内的光标或编辑框没有变化，也无法识别未暴露信息的密码框／选区。这是普通输入法兼容路径，不是可靠控件证明。它不读取输入框前文，也不发送文字处理请求。终端使用既有配置中的 Ctrl+Shift+V。

前文和文字处理仍要求可靠控件，发送范围和上限保持原设置。修改选中文字要求原控件、选区范围及复制文字摘要一致，终端和未知控件不能使用选区指令。正文和本地保护摘要不会因窗口兼容路径而发送到模型。

`review`／`confirm` 是内部 CLI 协议；UI 一次“输入”点击在程序内完成绑定和确认。成功输入、复制或发送状态不确定后，本次结果不能重复消费。快捷键发送与目标检查不是跨进程原子事务，也没有应用接收回执。
